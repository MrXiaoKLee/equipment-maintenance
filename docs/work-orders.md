# P3：故障报修、工单查询、分配与取消

## 功能入口

刷新前端，必要时重新登录，在「设备维护管理 → 故障工单」进入。后端本机8080、前端5173。设备台账的工单历史「查看」复用同一工单详情与动作记录弹窗。

本阶段完成待受理工单的创建、查询、分配和取消。处理记录追加、提交复核、退回与通过在P4实现；本阶段分配后的工单停留在处理中。

## 角色与账号

| 业务角色 | 可以执行 |
| --- | --- |
| 报修人员 `eq_reporter` | 提交报修；查看本人报修的工单、动作记录和设备历史；取消本人待受理工单 |
| 维护人员 `eq_maintainer` | 查看当前分配给自己的工单、动作记录和设备历史 |
| 设备管理人员 `eq_manager` | 查看项目全部工单、记录和设备历史；分配待受理工单；取消待受理工单 |
| 原版超级管理员（ID=1） | 开发调试时可执行以上动作，仍遵守设备状态、工单状态、版本和必填规则 |

多角色读取范围取并集；管理角色本身不包含报修动作。服务端构造当前访问身份，不接受客户端提供的角色、报修人或可读范围。

用于自己的演示时，以超级管理员进入「系统管理 → 用户管理」，分别创建报修、维护和管理账号，分配对应业务角色。启用维护账号并授予 `eq_maintainer` 后，才会出现在工单的维护人员选择中。分配业务角色后重新登录刷新权限；原版登录账号长度限制为2至20字符，演示账号宜使用短英文名。

接口验收创建的账号和设备均标注模拟用途；测试账号在验收结束后停用。它们不能代替自己的正式演示账号。

## 使用步骤

1. 报修人员点击「提交报修」，搜索在用设备，填写标题、现象、发生时间、初步类别及优先级。
2. 发生时间按北京时间填写，不能晚于提交时的服务端当前时间；无效日历日期会拒绝。
3. 选择设备后，表单显示当前账号可见的同设备未结束工单，最多展开前5条，并显示范围内总数。提交前重新查询并确认是否继续。其他账号不可见的工单不会用于提示，避免泄露他人报修信息。
4. 提交成功后生成 `WO-` 加32位UUID的工单编号，状态为待受理，记录提交人及服务端时间，并追加创建记录。
5. 管理人员打开待受理工单的「分配」，搜索有效维护人员，可填写分配说明。保存后变为处理中，记录维护人员及分配时间，并追加分配记录。
6. 本人报修或管理人员可以取消待受理工单，取消原因必填。取消后保留工单和原因，状态为已取消，不能再次分配或取消。
7. 点击「详情」查看原始报修信息和动作时间线；设备台账的「工单历史 → 查看」展示同一详情。

标题最多100字、现象2000字、取消原因2000字。分配说明最多1800字，为记录中附加维护人员身份预留空间。文字按纯文本展示。

## 查询与权限

工单列表支持工单编号模糊查询，设备、状态、类别、优先级及报修提交日期筛选。设备筛选允许查到停用或报废设备的既有工单；新报修的设备选择只提供在用设备。

管理人员可按报修人或维护人员的姓名、账号筛选；API也兼容人员ID精确筛选。普通报修或维护账号不能通过这些参数扩大范围。列表、详情、记录及设备历史都由后端核对当前业务角色；范围外工单返回业务404。

日期使用创建时间的左闭右开区间：结束日期转换为次日零时。默认创建时间倒序、工单ID倒序，每页10条，最大100条。维护人员选择同样分页且最大100条，使用关键词缩小候选范围。

## 一致性与记录

创建、分配、取消均使用READ_COMMITTED事务。先锁设备，再锁工单，动作写入和记录追加在同一事务；任一记录写入失败会回滚主表。时间线按记录时间、记录ID升序展示。

每次分配或取消提交读取时的版本，SQL同时限制当前状态和版本，并递增版本。不同页面同时分配和取消时，仅一个成功，另一个返回409，不追加重复记录。

报修创建与设备报废共用设备行锁：报废先完成则新报修拒绝；报修先完成则报废检查发现未结束工单并拒绝。已取消和已关闭不阻止报废。

记录保留动作类型、前后状态、说明、操作者ID、显示名快照和服务端时间；没有修改或删除工单、改写原报修内容、修改历史记录的接口。

## 验证

本阶段已有40项单元测试（含20项P2）及4项真实MySQL业务Mapper/事务测试通过。实际API检查覆盖身份伪造、角色和对象范围、有效维护人、取消原因、旧版本、设备历史及两种并发竞争。页面新增、已有工单确认、分配、取消、详情时间线、设备历史和状态筛选也已通过浏览器验收。详情见 `docs/verification.md`。

MySQL测试显式配置后才运行；未配置时默认执行40项单元测试并跳过4项MySQL测试，本机显式配置后44项全部执行且通过。使用专用连接上的临时业务表克隆，连接关闭即释放，常规业务表不被测试写入；账号关联只读，测试中的分配目标使用虚拟候选，实际目标资格另外通过API验证。临时表测试不覆盖正式外键约束和跨连接锁，跨连接竞争由本机实际API模拟数据验收补充。
