# P5 基础统计与工单导出

实现日期：2026-10-15。基于README第5.4、5.5节，统计设备与工单记录，不接入设备实时数据。

## 本地使用

已完成P4的环境仅需在项目库执行 `sql/006_statistics_export_menu.sql`，运行最新后端和前端，并重新登录。本机已执行006并验证重复执行，不必再次导入。

006增加「设备维护管理 → 统计分析」页面及「故障工单 → 导出工单」按钮。统计授权给管理角色 `eq_manager`；导出授权给管理、报修、维护三类角色。不会自动给现有账号分配业务角色。平台管理员沿用项目原有授权规则。

日常启动继续使用已有的本地数据库和Redis配置，不需要新增环境变量、服务或依赖。后端改动需重新打包，前端使用原有启动方式。

1. 管理人员登录，进入「统计分析」。默认统计全部历史、全部设备。
2. 可选择提交日期区间及一台设备，点击「查询」。日期对应报修提交时间，不是故障发生时间或关闭时间。
3. 读取页面显示的工单范围及北京时间更新时间；查询手动刷新，没有自动轮询。
4. 每个图表可切换为表格，查看分类及精确数量。窄屏采用单列图表；390像素宽度已实测无页面横向溢出。
5. 日期与设备条件写入当前页面URL，刷新可以恢复条件。「重置」恢复全部历史、全部设备。
6. 进入「故障工单」，搜索并核对列表范围，再点击「导出工单」。导出所有符合条件且本人可见的工单，不局限当前分页。

## 统计口径

| 指标 | 计算规则 |
| --- | --- |
| 设备总数、设备使用状态 | 始终统计全库设备，不受日期或设备筛选影响；使用状态为在用、停用、报废 |
| 工单总数 | 所选提交日期及设备范围内全部工单，包含已取消 |
| 未结束工单 | 待受理、处理中、待复核数量之和 |
| 工单状态分布 | 待受理、处理中、待复核、已关闭、已取消，五项之和等于当前工单总数；缺少的状态补0 |
| 故障类别分布 | 同一工单范围，排除已取消；按数量降序、类别代码排序 |
| 设备报修次数前10名 | 同一工单范围，排除已取消；按数量降序，相同次数按设备编号升序，最多10台 |
| 平均闭环时长 | 仅已关闭工单，平均值为 `closed_time - create_time`，以小时显示并四舍五入到两位小数 |

平均闭环时长包含等待、处理、复核；不能称为MTTR，也不据此推算MTBF、可用率或质量合格率。没有已关闭工单时返回 `null`，页面显示「无数据」；存在快速关闭工单时，四舍五入后的0小时是有效结果。

日期格式 `yyyy-MM-dd`，按Asia/Shanghai解释；开始日期包含当天00:00:00，结束日期转换为次日00:00:00且不包含该时刻。支持仅传一侧日期。非法日历日期、格式错误、开始晚于结束返回业务码400。允许年份为1000至9998，避免次日边界溢出。

统计在一个只读、REPEATABLE_READ事务中执行多条汇总SQL。图表展示同次查询的数据；没有新增统计缓存或Redis数据模型。页面拒绝过期响应覆盖新查询，查询失败时保留上次成功的数据、范围及更新时间，并显示失败提示。

四个面板使用横向柱状图及直接数字标注，数量轴采用整数刻度。设备数量单位为台，工单数量为条；图表具有包含分类、数量和单位的文字描述，也提供明细表。全零结果展示「当前范围内无数据」，不绘制有面积的占位数据。

## 接口契约

`GET /equipment/statistics/overview`，权限 `equipment:statistics:query`，服务层再次检查管理角色。

| 查询参数 | 含义 |
| --- | --- |
| `beginDate`、`endDate` | 可选提交日期边界，`yyyy-MM-dd` |
| `equipmentId` | 可选正整数设备ID；JSON返回的设备ID使用字符串 |

成功返回若依 `code/msg/data` 包装，`data`字段如下：

| 字段 | 类型与含义 |
| --- | --- |
| `equipmentTotal` | 整数，全局设备数量 |
| `orderTotal`、`openOrderCount`、`closedOrderCount` | 整数，当前工单范围总数、未结束数、已关闭数 |
| `averageClosedHours` | 数字或null，平均闭环小时数 |
| `equipmentStatuses`、`orderStatuses`、`faultCategories` | 数组，每项为 `code/label/count`，字典缺失时label回退代码 |
| `topEquipment` | 数组，每项为 `equipmentId/equipmentCode/equipmentName/count` |
| `generatedTime` | 北京时间，`yyyy-MM-dd HH:mm:ss`，表示本次查询生成时间 |

`POST /equipment/workorder/export`，权限 `equipment:workorder:export`。使用 `application/x-www-form-urlencoded` 表单参数；成功返回XLSX，失败返回若依JSON业务错误。

筛选支持 `workOrderNo/equipmentId/status/faultCategory/priority/beginDate/endDate/reporterId/handlerId/reporterName/handlerName/openOnly`。与列表共用筛选SQL及服务层归一化；传入的内部时间边界由服务端按日期重算。分页参数不影响导出，排序固定为提交时间、工单ID倒序。

## 导出范围与文件

| 账号角色 | 可导出范围 |
| --- | --- |
| 报修人员 | 本人报修 |
| 维护人员 | 当前分配给本人 |
| 管理人员 | 全部工单 |
| 多角色 | 以上范围取并集，不重复导出 |

筛选参数只能缩小范围，不能通过伪造报修人或处理人扩大本人权限。后台读取最多1001条探测上限：1000条允许，1001条及以上直接拒绝并提示缩小条件，不截断文件。空结果允许导出只有表头的工作表。

导出16列，顺序为：工单编号、标题、设备编号、设备名称、故障类别、优先级、故障现象、报修人、维护人员、工单状态、故障发生时间、报修提交时间、分配时间、最近提交复核时间、关闭时间、取消时间。

类别、优先级和状态转换为中文标签，字典缺失时保留原代码；时间格式为 `yyyy-MM-dd HH:mm:ss`。没有发生的流程时间留空。采用专门导出对象，不输出内部ID、版本或完整处理时间线；需要原因、措施、每轮结果和复核说明时查看工单详情。文本按Excel字符串单元格写入，测试核对公式形式的输入不会形成公式单元格。
